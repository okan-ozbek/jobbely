# Decision: Hugging Face public Workable integration

**Status:** Implemented; five vacancies and matching job features imported. Exact-run technical inventory verified, employer scope/access/display reviews pending. Source candidate and unscheduled. Recorded 6 October 2026, Europe/Amsterdam.

## Discovery and rationale

The [official employer homepage](https://huggingface.co/) explicitly links its Careers footer to the [Workable huggingface account](https://apply.workable.com/huggingface/). The guessed join-us URL redirects to a community organization, not an employer careers page, and is not configured. The Workable board's hosted HTML is a JavaScript shell; no upstream scripts, browser challenges or application forms are executed.

The public widget at `https://apply.workable.com/api/v1/widget/accounts/huggingface?details=true` supplies six published entries and complete descriptions. Five are specific vacancies. The sixth, native shortcode `0BD8C06DB3`, is a Wild Card open application inviting applicants to design a role; it is counted as an exclusion rather than published as a vacancy. The exclusion is limited to this employer's exact title, alongside existing generic non-vacancy rules.

The board explicitly advertises [llms.txt](https://apply.workable.com/huggingface/llms.txt), which links to its [all-open-positions Markdown inventory](https://apply.workable.com/huggingface/jobs.md). That inventory independently lists the same six entries with native shortcodes, titles, departments, dates and locations. Its five vacancy identities match the exact imported widget snapshot after the same Wild Card exclusion. Both employer/provider robots policies permit the observed public requests.

The [employer terms](https://huggingface.co/terms-of-service), [employer privacy notice](https://huggingface.co/privacy), [Workable privacy notice](https://www.workable.com/privacy) and [public widget documentation](https://help.workable.com/hc/en-us/articles/115012801727-How-to-embed-jobs-on-your-website-job-widget) are captured. Access/display review remains pending; no employer consent, review identity or approved-document records are invented. Public repository licenses do not establish recruitment-advertisement rights, and provider widget documentation does not independently approve this application's display. Technical reconciliation is separate from employer/entity/channel review.

## Adapter and audit invariants

- Stable company/source ID `hugging-face`, provider `workable`, account `huggingface`, Wave C. The local N/A logo awaits vector review. Candidate state, scheduling disabled.
- The shared transport adds only GET for the exact account widget with one `details=true` parameter. Other accounts, filters, duplicate query parameters, fragments, private API routes, HTML requests and writes fail. Existing pacing, retries, redirects, timeout and byte limits remain enforced.
- Validate employer name, unique ten-character native shortcodes, full readable descriptions, and native detail/application links before returning postings. A foreign employer/link, duplicate identity, malformed date or missing description fails the whole extraction, including excluded entries. No empty successful snapshot is inferred from hosted HTML.
- Recheck the full decoded aggregate and preserve both responses. Any posting/description/metadata drift fails extraction; reordering alone does not. The published widget is one aggregate bounded to 10,000 entries, not a paginated private account API.
- Keep the complete advertised description, department/function labels, employment label and original URLs. Explicit telecommuting true maps to remote; false/null/absent does not establish onsite work or worldwide remote eligibility. Public locations include city/region/country, while locations marked hidden retain country only. Date-only `published_on` values use midnight UTC as a normalization convention, not an observed posting time; absent dates remain null.
- Official transport accepts Markdown only at this account's exact jobs.md URL, retaining robots, public-address/DNS, timeout, byte and redirect checks. The parser recognizes its known full-position table, reads native titles/links safely, and rejects malformed, duplicate or unproven empty inventories. It neither runs HTML/scripts inside titles nor treats embedded URLs as an exhaustive inventory.
- Employer scope/access/display review remains pending. A technical match does not enable verified scheduling or closure. Raw feed, policy and Markdown records remain in ignored backend data directories; checked-in audit evidence contains hashes, IDs, counts and review limits.
