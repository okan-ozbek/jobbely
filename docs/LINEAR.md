# Decision: Linear public Ashby import and regional inventory gaps

**Status:** Implemented; 31 jobs imported locally with full descriptions and matching features. Technical employer coverage partial; source candidate and scheduled, with employer scope/access/display reviews pending. Recorded 7 October 2026, Europe/Amsterdam.

## Discovery and rationale

The [official careers page](https://linear.app/careers) exposes 24 distinct native `/careers/<uuid>` links. Its public hydration and the [Product Engineer detail](https://linear.app/careers/0c7c2e26-0a98-42cf-a47c-9a3999fb513b) identify [Ashby board Linear](https://jobs.ashbyhq.com/Linear). The public version-1 aggregate advertises 31 listed postings with complete descriptions and original application links; zero non-vacancy entries were excluded. All 24 visible native UUIDs match the exact imported feed. Seven additional North America UUIDs have same-title Europe/London counterparts in the visible inventory. They remain distinct stored postings and unreconciled IDs; grouped regional labels do not prove independently reviewed identity equivalence or whole-employer coverage.

Native UUID reconciliation maps exact employer URLs to the case-preserved `Linear` board. Hosted metadata advertises lowercase `linear`; both public board spellings returned identical posting IDs, descriptions and metadata apart from original URL board casing. Auditing maps only this observed alias to `Linear`, alongside the pre-existing ElevenLabs alias. Other board spellings retain their case, and ingestion preserves original employer/application URLs.

Every posting sets `shouldDisplayCompensationOnJobPostings: false`. Structured compensation remains suppressed by the existing adapter; salary/equity language already in the employer's full description is preserved. No pay range is inferred or calculated.

The application owner's continuing onboarding request authorizes local integration/display, and the earlier all-source instruction enables scheduled refreshes. Captured [terms](https://linear.app/terms) and [Acceptable Use Policy](https://linear.app/legal/aup) are effective 9 June 2026; the AUP includes automated-service access and extraction outside published API restrictions. [Privacy](https://linear.app/privacy) is effective 17 March 2025. These policies and [Ashby API documentation](https://developers.ashbyhq.com/docs/public-job-posting-api) remain unreviewed evidence. Their service context does not establish career republication rights. Employer permission and worldwide legal-entity scope remain unverified, without invented consent, reviewers or approved document hashes. Existing explicitly blocked employer plans remain effective. Public scripts were read as text; no applications or forms were submitted.

## Runtime invariants

- Stable company/source ID `linear`, case-preserved Ashby board `Linear`, Wave C, canonical careers URL and shared N/A logo pending vector review. Scheduling follows [SCHEDULING.md](SCHEDULING.md) independently of verification.
- Reuse `https://api.ashbyhq.com/posting-api/job-board/Linear?includeCompensation=true` through the existing adapter and bounded transport. No new adapter, private API, credentials, ingestion destination, transport allowlist or public API schema is required.
- Preserve complete sanitized HTML/text, native posting UUIDs, titles, original URLs, department/team, primary/secondary locations, employment/workplace labels and publication dates. Respect explicit compensation display flags; unknown optional fields remain unknown.
- Native identities require HTTPS on exact `linear.app`, a full lowercase UUID and canonical career path. Reject credentials, custom ports, queries/fragments, shortened IDs and extra title/application segments; allow a trailing slash. Visible links supply inventory while embedded URLs supply discovery. Equal titles do not merge regional UUIDs.
- Audit uses the exact successful extraction and run ID without another feed fetch. Technical matching, employer approval and closure remain distinct. Candidate refreshes cannot advance missing counters or close absent jobs; blocked-plan and removal-quarantine gates remain unchanged.
- Raw descriptions, policies and diagnostics stay in ignored backend data. Checked-in evidence contains compact identities, hashes, counts and limitations.
