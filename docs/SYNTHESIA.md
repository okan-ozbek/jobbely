# Decision: Synthesia public Ashby widget import

**Status:** Implemented; 44 specific vacancies imported locally with full descriptions, native compensation and matching features. Technical employer coverage partial; source candidate and scheduled, with independent inventory/automatic attribution and employer reviews pending. Recorded 7 October 2026, Europe/Amsterdam.

## Discovery and rationale

The [official careers page](https://www.synthesia.io/careers) embeds an `ashby-jobs` widget. Its inline script declares literal `JOB_BOARD_NAME = "synthesia"` and constructs a public Ashby posting-api request from it, then renders listed jobs with department/team and location filters. This identifies [board synthesia](https://jobs.ashbyhq.com/synthesia) without executing employer scripts or submitting an application.

The public version-1 aggregate contains 45 listed entries with complete descriptions. Existing generic non-vacancy rules exclude the [Marketing General Application](https://jobs.ashbyhq.com/synthesia/7b8a6552-4960-43f1-a15c-231be624ba1a), leaving 44 specific vacancies. One vacancy advertises structured salary/equity compensation with one geographic tier. Native summaries, component text, currency and interval are preserved without calculating ranges.

Neither employer raw HTML nor the hosted Ashby shell exposes visible posting UUID inventory. The automatic audit parser also does not resolve the concatenated widget request as an employer-to-board link. The observed explicit widget configuration is discovery evidence, while independent attribution/traversal and all 44 native posting identities remain unreconciled by the audit. A successful aggregate import does not establish whole-employer completeness or reviewed worldwide legal-entity scope. No placeholder vacancies or zero-jobs claims are made from the empty shell.

The application owner's continuing onboarding request authorizes local integration/display, and the earlier all-source instruction enables scheduled refreshes. Captured [customer terms](https://www.synthesia.io/legal/customer-terms-of-service) are effective 20 July 2026; [user terms](https://www.synthesia.io/legal/user-terms-of-service) and [Acceptable Use Policy](https://www.synthesia.io/legal/acceptable-use-policy) were updated 23 February 2024. [Privacy](https://www.synthesia.io/legal/privacy-policy) is effective 1 October 2026. The AUP restricts scraping for AI model/tool creation or training; Jobbely's collection, classification and matching remain deterministic without runtime AI. These service policies and [Ashby API documentation](https://developers.ashbyhq.com/docs/public-job-posting-api) remain unreviewed evidence rather than inferred career republication permission. Employer retrieval/display and scope reviews remain pending without invented consent, reviewers or approved document hashes. Existing explicitly blocked employer plans remain effective.

## Runtime invariants

- Stable company/source ID and Ashby board `synthesia`, Wave C, canonical careers URL and shared N/A logo pending vector review. Scheduling follows [SCHEDULING.md](SCHEDULING.md) independently of verification.
- Reuse `https://api.ashbyhq.com/posting-api/job-board/synthesia?includeCompensation=true` through the existing adapter and bounded transport. No new adapter, private API, credentials, ingestion destination, identity parser, transport allowlist or public API schema is required.
- Preserve complete sanitized HTML/text, native posting UUIDs, titles, original job/application URLs, department/team, primary/secondary locations, employment/workplace labels, publication dates and advertised salary/equity compensation. Unknown optional fields remain unknown.
- Count the excluded general application explicitly. Empty employer/hosted HTML does not prove an empty or complete inventory. Widget configuration is separate from independently visible identity reconciliation and manual employer scope approval.
- Audit uses the exact successful extraction and run ID without another feed fetch. Technical matching, employer approval and closure remain distinct. Candidate refreshes cannot advance missing counters or close absent jobs; blocked-plan and removal-quarantine gates remain unchanged.
- Raw descriptions, discovery HTML, policies and diagnostics stay in ignored backend data. Checked-in evidence contains compact identities, hashes, counts and limitations. No forms or applications were submitted.
