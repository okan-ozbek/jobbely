## 1. Reproduced failure and correct interpretation

The stored Airbnb **Early Career Mobile Software Engineer, Quality Platform**, posting `2a4476c8-2081-4da1-8ff2-d6abd653cdb5`, contains the qualifications supplied by the user. On 8 October, the application PDF adapter, analysis workflow, frontend profile allowlist and pure scorer reproduced **100% fit, strong band, 100% coverage (2/2), zero required gaps and zero unresolved requirements**. Processing was transient. No private file contents, profile, identifiers, employment history or extracted candidate passages are included here or saved as fixtures.

The two counted criteria were one programming-language alternative group and a one-year experience threshold. A separate extraction of the pasted job text also produced one required skill group, one required duration, seven contextual skill groups, a contextual degree and zero `unparsed` entries. This is not solely a file-reading failure.

| Reported wording    | Current finding                                                                                                           | Required behavior to label and test                                                                                                          |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Automated tests     | `test-automation` recognizes automated testing, but the automated-tests phrasing is absent                                | Recognize the activity and its writing/maintenance scope; merge synonymous references to the same obligation                                 |
| Espresso / XCUITest | Neither tool is registered; the framework sentence contains unresolved terms but is contextual                            | Recognize distinct mobile UI testing tools; retain the examples as examples, rather than demanding all named tools                           |
| Testing             | Basic testing concepts/test pyramid are not represented as a qualification                                                | Extract software-testing knowledge with context; do not equate every occurrence of testing, including non-software testing, with expertise   |
| CI/CD               | The ID exists and the job contains recognized occurrences; qualification wording remains contextual                       | Distinguish integration responsibilities, present knowledge and eagerness to learn; lack of a highlight is not always lack of recognition    |
| Applied AI/LLMs     | LLM recognition exists in the relevant sentences, but the activity and curiosity/learning modality are not qualifications | Preserve AI-assisted test creation as an activity; curiosity is not production LLM expertise                                                 |
| Bachelor's degree   | Parsed as a degree constraint, but contextual; bare “or equivalent” is not represented as an equivalence route            | Treat education separately from skills. Retain the unspecified equivalent route as unresolved, rather than inventing an experience threshold |

The section classifier leaves these blocks `unknown/contextual`; the importance rules recognize knowledge-of and explicit required cues but miss several exposure/understanding/degree forms. [Requirement extraction](../backend/src/domain/matching/requirements.ts) consequently omits them from scored qualifications. [Assessment coverage](../backend/src/domain/matching/assessment-coverage.ts) counts only identified non-contextual criteria, so its 2/2 cannot detect omitted requirements. [Scoring](../backend/src/domain/matching/score.ts) normalizes available dimensions and can reach 100; [presentation](../frontend/src/features/resume/MatchMetrics.tsx) labels this fit on assessed criteria. The label is insufficient protection when the extraction silently drops qualifications.

There is no defensible corrected percentage yet: it needs an adjudicated obligation inventory and evidence decisions. Espresso and XCUITest belong to illustrative alternatives alongside other frameworks; missing each name is not an independent mandatory gap. Absence from a resume means not evidenced, not incapable. Internship/project exposure is explicitly acceptable in this role and cannot be replaced by a professional-employment-only rule. English collaboration also needs an explicit requirement/review item; residence cannot establish language proficiency.

First acceptance case: all meaningful qualification clauses survive extraction, testing examples do not become an AND list, education equivalence stays uncertain when undefined, and incomplete interpretation cannot yield a confident perfect headline. Create fictional regression profiles with these characteristics; never commit the attached private resume.

## 2. Options and decision experiment

| Option                               | Implementation                                                                                                                                                                 | Strength                                                                                          | Main limitation / operating cost                                                                              | Decision                                                                                                     |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| A. Rules and established taxonomy    | Strengthen section/modality grammar, tokenize activities, normalize through a pinned ESCO/O*NET crosswalk plus local product names                                             | Fast, repeatable, easy to inspect; no model service                                               | Ongoing grammar maintenance; open-ended paraphrases and equivalence remain brittle                            | Required baseline and immediate repair; measure its ceiling                                                  |
| B. Compact NLP models                | Benchmark open-type entity/span extraction plus clause classification, embeddings and a separately evaluated entailment comparator                                             | Smaller inference workload; can recognize unseen names and paraphrases                            | Entity recognition does not solve obligation logic; relevance is not entailment; domain labels still required | Strong candidate when host resources are limited                                                             |
| C. Hybrid self-hosted language model | Extract public job obligations with a pinned instruction model; validate sources and logic; retain deterministic direct comparisons and bounded model assistance for ambiguity | Handles compound wording and unfamiliar activities without requiring every phrase in the registry | Model omissions/hallucinations, inference resource cost, validation and review work                           | Recommended direction, conditional on benchmark gates                                                        |
| D. Hosted language model             | Same extraction/evaluation contract using a remote service                                                                                                                     | Easier infrastructure experiment; potentially broader model choices                               | Token costs, external dependency and changed data boundary                                                    | Public-job benchmark option only after deliberate provider decision; private resume egress is not authorized |
| E. Supervised extraction/ranking     | Train/fine-tune clause or pair models on adjudicated labels; learn ranking from independent relevance judgments                                                                | Can optimize recurrent domain-specific failures                                                   | Labels, drift, overfitting and biased feedback; current data is not a training set                            | Later, only after A–C reveal a persistent measurable gap                                                     |

[ESCO](https://esco.ec.europa.eu/en/use-esco) provides scoped concepts and stable identifiers; [O*NET](https://www.onetcenter.org/database.html) provides occupational skills, tasks and technology examples. Use them as versioned normalization/reference sources, not complete employer requirement lists. Review licenses/attribution and many-to-many mappings before import; never infer a requirement just because an occupation normally uses a skill. Keep existing Jobbely IDs stable and allow unmapped open-text capabilities.

[spaCy's token/span rules](https://spacy.io/usage/rule-based-matching) are an example of richer rule-based NLP, not a mandatory rewrite into Python. [GLiNER](https://arxiv.org/abs/2311.08526) is a candidate for compact open-type entity extraction, not proof of ATS accuracy. Evaluate tools, capabilities, qualifications and activity spans separately; a coffee reference must not become Android Espresso expertise. [Android Espresso](https://developer.android.com/training/testing/espresso) and [Apple XCUIAutomation/XCTest](https://developer.apple.com/documentation/xcuiautomation) establish distinct UI testing technologies, not candidate proficiency.

Benchmark one small instruction model and one larger instruction model on the actual host; pin license, weight digest, quantization, prompt and runtime. Do not choose solely from general leaderboards or assume a larger model passes. No weights or runtime have been installed by this planning task. The existing [Ollama adapter](../backend/src/infrastructure/semantics/ollama.ts) is a reusable starting point, but has no established live accuracy. Structured output constrains shape, not truth; [Ollama documents schema output](https://docs.ollama.com/capabilities/structured-outputs) and [local-only configuration](https://docs.ollama.com/faq#how-do-i-disable-ollama-cloud-features).

Use identical frozen evaluation data for A–C and an optional public-only D. Run ablations: rules alone, rules plus taxonomy, compact NLP, language-model extraction, then hybrid extraction/comparison. Report accuracy, failure/abstention rates, latency, resource use and cost together. Select the cheapest strategy that meets all quality gates; if none passes, keep the review state and improve the experiment.

## 3. Proposed pipeline and contracts

1. **Read the document.** Preserve HTML headings, bullet/list context and exact canonical offsets. Check missing sections, truncated text and malformed descriptions. PDF/DOCX reading remains local with explicit warnings; extraction quality is tested independently from matching quality.
2. **Inventory clauses before normalization.** Every meaningful body clause has a disposition: qualification, responsibility, employer context, benefit/application/legal information, or unresolved. Missing disposition blocks publication. Complete accounting does not establish that dispositions are semantically correct; the independent benchmark measures that.
3. **Extract open-vocabulary obligations.** Retain action, object, domain, depth, actor, required/preferred/learning/conditional modality, allowed evidence sources, tenure, examples, alternatives and exact source spans. Unknown names remain typed text requirements and cannot disappear because no canonical ID exists. Limit large documents through overlapping chunks with deduplication; failed or omitted chunks mark the whole interpretation incomplete.
4. **Normalize and validate.** Map synonyms to stable concepts where justified. Keep tools, testing methods, behaviors, education and eligibility separate. Validate schema, quoted spans, offsets, expression references, polarity and stated numbers; reject fabricated tools, years and equivalent routes. Disagreement between strategies stays reviewable; never union all predictions into mandatory criteria.
5. **Publish public features.** Run model work outside database transactions in a separate bounded enrichment worker. Publish against current content hash through existing race protections. Store interpretation state and full extraction/model/schema/ontology identity. Job syncing continues when enrichment fails; the original listing remains visible with incomplete analysis status. Matching should not call a model for every catalog description.
6. **Analyze candidate evidence once per revision.** Preserve separate performed, assisted, observed, listed, learning and denied propositions with role/source linkage. Redact contact/header identity before any future host model inference. Candidate correction changes the relevant evidence without triggering model calls on every keypress. Preserve original spans in transient review state and distinguish user confirmation from verified proficiency.
7. **Retrieve relevant jobs/evidence.** Start with an exact baseline and a union of canonical/lexical and semantic retrieval. Benchmark 100–300 job candidates, then 20–50 detailed comparisons. Preserve explicit filters and source freshness. A missing shortlist candidate has not failed a qualification; retrieval failures are measured separately.
8. **Compare each obligation.** Direct, unambiguous evidence can use rules. For paraphrases, evaluate a small premise/hypothesis classifier or a bounded instruction model. Retrieve candidate evidence before comparison; no found passage is not proof of inability. Return supported, partial, not evidenced, contradicted or unknown with paired provenance. General coding, Python or backend tenure cannot imply mobile testing expertise.
9. **Score and explain with pure policy.** Apply nested alternative/conjunction logic, preserve uncertainty, separate role relevance and eligibility, and retain an immutable ranking snapshot for pagination. A model's confidence or similarity output never becomes a fit percentage.

The existing [semantic model](../backend/src/domain/matching/semantic-model.ts), [extractor port](../backend/src/ports/semantic-extractor.ts), [validator](../backend/src/domain/matching/semantic-validation.ts) and [requirement algebra](../backend/src/domain/matching/requirement-logic.ts) cover part of steps 2–4 and 9. Candidate semantic inference, labeled entailment, public semantic publication and semantic retrieval are not live implementations. Extend ports/adapters; do not put model requests in domain scoring or import backend internals into the frontend.

[Sentence Transformers](https://www.sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html) documents efficient retrieval followed by bounded reranking. Its [model documentation](https://www.sbert.net/docs/cross_encoder/pretrained_models.html) distinguishes relevance/similarity from natural-language inference. Their published scores are not job-matching validation. Prototype, for example, a MiniLM retrieval/reranking baseline separately from an NLI DeBERTa comparator; verify licenses and domain performance before selection. Benchmark exact retrieval before [pgvector approximate indexes](https://github.com/pgvector/pgvector#filtering), especially under filters.

## 4. Scoring rules that prevent this failure

Keep three questions separate: did we interpret the job, what evidence supports its qualifications, and how relevant is the work? Do not describe a number as an employer's ATS score or interview probability.

For fully inventoried, applicable obligations, expose separate required and preferred evidence coverage. Initially equal-weight independent obligations; change weights only through validation and explicit policy review. An AND route needs all constituents; an OR route needs one valid route. Examples are neither mandatory tools nor extra denominator entries. Responsibilities may affect role relevance but cannot compensate for a missing required qualification. Degree/equivalence and allowed internship/project evidence need their own logic.

For each obligation use lower/upper evidence credit: supported 1/1, partial 0.5/0.5, not evidenced or denied 0/0, unknown 0/1. The existing algebra supplies an experimental starting point; the 0.5 partial value is a policy proposal, not a calibrated measurement. Unknowns stay in the denominator. An unspecified equivalence route stays unknown; it is not satisfied by arbitrary years.

Expose a range only when the obligation inventory is complete enough to bound it. If whole clauses or sections are unresolved, label **Incomplete interpretation — review qualifications**, rather than displaying a reassuring upper bound. Interpretation accounting and benchmark reliability must accompany this state; there is no absolute proof that an automated parser found every implicit expectation.

A perfect evidence percentage requires no unresolved interpretation, unknown applicable qualifications or unsatisfied required obligations. It means full support for interpreted qualifications, not guaranteed suitability. Do not force every result below 100 or clamp a bad score to 99. Adding an unmet required obligation must lower coverage; adding an unknown obligation must widen uncertainty/lower its bound. Repeating keywords, changing an employer brand or adding benefits must not improve the result.

Ordering should separate satisfied required qualifications, evidenced gaps and review-required cases, then use evaluated role relevance and stable tie-breakers. Missing evidence must not be an automated hiring rejection. Percentages, bands and thresholds are tuned on validation labels, not chosen to make this one resume rank lower. No private feedback or company popularity can establish qualification evidence.

## 5. Independent benchmark and proposed release gates

Build a versioned annotation specification and error taxonomy before model selection. Label requirements and candidate evidence separately, then pair them. At least two reviewers independently label an initial calibration sample; adjudicate disagreements and record disagreement rates. Agent/model-generated labels are drafts, not independent ground truth. Reviewers may choose ambiguous/insufficient evidence rather than invent a binary answer.

Starter benchmark: **300 public jobs** across the five supported functions (60 each), **30 fictional resume families**, **900 selected job/profile pairs**, and **1,000 atomic contrast cases**. Cover mobile/backend/data/security engineering, junior/senior roles, sparse/long descriptions, unfamiliar tools, malformed headings, compound qualifications, equivalents, hard negatives, negation/learning, and layout variants. The broader catalog may be audited, but unsupported recommendation functions/languages remain explicit rather than silently claiming validation.

Split jobs 150 development / 75 validation / 75 frozen test; split fictional families 10/10/10; select 300 pairs per split. Keep employer/template/near-duplicate job groups and resume/paraphrase families entirely within one split; adjust counts if grouping requires it. Hold out unfamiliar concept names. Keep the supplied Airbnb example as a known development regression, never as evidence of generalization. Real private resumes require a separate opt-in protocol and cannot be committed, harvested from account data or used as automatic training material.

| Layer                         | Metric / adversarial checks                                                                | Proposed acceptance target, not an achieved result                                                                                               |
| ----------------------------- | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Document and clause inventory | Missing/truncated content; qualification disposition precision/recall; empty/failed inputs | Zero silently skipped chunks; all failures reported; 100% source accounting in published features                                                |
| Requirement extraction        | Obligation precision/recall including unfamiliar names and low-obligation exposure forms   | At least 98% precision and 95% recall overall; at least 90% recall in each adequately represented function/critical slice                        |
| Logic and scope               | OR/AND, examples, equivalent routes, negation, learning and activity tenure                | At least 95% exact logic accuracy; zero known critical failures in the dedicated safety regression set                                           |
| Evidence comparison           | Supported/partial/unknown confusion matrix; false fully-supported decisions                | At most 1% false-full decisions on independent hard negatives, with at least 95% supported-evidence precision and explicit abstention accounting |
| Sparse perfect-score failure  | Remove evidence, insert unknown qualifications, alter modality, add unseen tools           | Zero confident-perfect outcomes for cases labeled incomplete or containing an unmet required obligation                                          |
| Retrieval                     | Relevant-job recall@K; evidence-span recall before pair classification                     | At least 95% labeled relevant-job recall at selected K overall, no supported-function slice below 90%                                            |
| Ranking                       | nDCG@10, top-10 critical gaps, independent pair ordering                                   | Beat the frozen rules baseline with an employer/family-clustered confidence interval; no slice loses more than two absolute points               |
| Explanation/privacy           | Exact provenance, truthful uncertainty, source borrowing, injected instructions            | No unsupported full decisions in critical tests; no candidate payloads in logs, persistence, queues or outbound requests                         |
| Operations                    | Warm/cold p50/p95, concurrent load, RAM/VRAM, timeouts, cost and pagination                | No unexplained regression against the frozen host baseline; failure preserves review status and stable pages                                     |

Publish sample counts, denominators and 95% intervals, not just a passing average. Cluster ranking intervals by employer and resume family because pairs are correlated. Report raw recalls and attempt counts so abstention/timeouts cannot hide false negatives. A small test set cannot certify a 1% failure bound: expand independent negatives until the chosen upper confidence bound supports that claim, or say the risk remains unverified. Report exposure/learning, unknown-tool and degree-equivalence slices separately; averages cannot conceal the Airbnb failure class.

Tests written by the same agent as the parser establish regressions, not held-out accuracy. Existing 18-case development evaluation is reusable plumbing, not the final benchmark. Once a test example has guided a fix, move it to development and replenish the frozen test cohort before making a new accuracy claim.

## 7. Performance, cost and privacy budget

Persist/copy only public job features and embeddings. Cache them by posting content hash plus extractor/schema/ontology/model/prompt identity. Admission control and bounded batches prevent public ingestion from starving private requests. Run public enrichment asynchronously, outside posting transactions; cap shared model concurrency independently of ingestion worker count. A changed extractor requires backfill and readiness accounting.

Benchmark exact versus approximate retrieval and different shortlist sizes. Never solve accuracy by running an instruction model against every job for every resume. Candidate propositions and embeddings remain transient, scoped to the reviewed revision, absent from logs, disk-backed queues and shared caches. Cancelled/replaced input cannot restore old results. A fallback must disclose its mode and interpretation limitations; it cannot silently claim semantic completeness or reuse another strategy's cursor.

Provisional service targets for the host experiment: warm deterministic review within 2 seconds, warm top-20 retrieval/comparison within 5 seconds at five concurrent fictional sessions, bounded cold semantic review within 15 seconds or an explicit progress/review state. These are proposed budgets, not measured guarantees. Establish available production RAM/GPU, queue wait, job update rate and sustained throughput before committing to a model size. If C cannot meet the budget, compare B or public-only model extraction with deterministic/private comparison; don't weaken accuracy gates.

For a hosted public-only experiment, calculate cost as changed jobs × (input tokens × input rate + output tokens × output rate), plus retries and evaluation. For self-hosting include compute hours, resident weights/KV memory, concurrency, storage for public embeddings and operator time. Measure tokens and throughput from samples; no provider-price or hardware assumptions are established by this plan. Review model and taxonomy licenses before release.

The existing user decision is host-based inference. Remote private model processing would require a new explicit data-boundary decision. Preserve [RESUME_PRIVACY](RESUME_PRIVACY.md), parser worker isolation and generated strict profile contracts. Disable and verify model payload logging/telemetry; loopback alone does not prove privacy. Employer text and resumes are untrusted input, with no tools or ability to alter instructions, URLs or scoring policy.
